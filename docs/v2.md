# Mothlight v2 — experimental screenplay workspace

This branch changes the creative workflow without modifying the v1 main branch.

## Start

1. Check out the v2 branch (git switch v2).
2. Run bun install to install Tiptap and update the dependency lock.
3. Stop both studios, then run bun run clone:v2 **once** to clone your original work, or omit the command to start a fresh v2 database.
4. Start bun run dev and open http://localhost:3000.

The clone uses SQLite VACUUM INTO for a consistent database snapshot, copies original media files and cancels queued/running jobs **only in v2**. It refuses to overwrite an existing v2 destination.

**Isolation:** main uses .mothlight by default; v2 uses .mothlight-v2 by default. Set MOTHLIGHT_V1_DATA_DIR for a nonstandard source directory and MOTHLIGHT_V2_DATA_DIR for a nonstandard v2 destination. Runtime v2 deliberately ignores the old MOTHLIGHT_DATA_DIR so the old studio stays untouched.

## Workflow

1. Open a project. Its principal view is a single continuous Tiptap screenplay.
2. Enter headings/action/dialogue directly, or choose **Import Fountain** to replace the screenplay text with a Fountain/plain-text file.
3. Hover a newline-delimited line and click + to attach a take. Multiple takes stack vertically and expand the line height. Long text wraps visually without creating extra anchor lines.
4. Add a manual prompt, video generation service/model, duration, resolution, aspect ratio, sound setting and optional World style.
5. Paste, drag, upload or choose storyboard images from the World asset grid; optionally generate additional still frames with Nano Banana or GPT Image.
6. Generate a Seedance video or run a configured custom video adapter. You can also import an externally generated video. Production shows generation jobs.
7. Once a video has been assigned, the take's inputs are immutable. Forking makes a new editable draft using the same inputs.
8. Drag takes between lines or within a line. Uncheck Include in Resolve handoff to keep an alternative out of the cut.
9. Download the **Resolve handoff** ZIP: ordered video EDL, original MP4 media, Fountain screenplay, and timing manifest. Finish soundtrack and edits in DaVinci Resolve.

## Line association

Each screenplay line is a custom Tiptap node with an immutable lineId managed by the UniqueID extension. The database stores takes separately from screenplay text with anchor_line_id and sort_order fields. Insertions above a line do not change a take's anchor. When a line is deleted its takes move to the nearest surviving preceding line, or the next surviving line if there is no previous. Reordering tiles changes take positions, not the original video. The document revision counter rejects stale concurrent saves.

## Architecture

- v2_screenplays: project ID, editor JSON document, revision and updated timestamp.
- v2_takes: linked project, line ID, position, options, manually entered prompt, referenced media, visual style, output media, job ID and inclusion flag.
- Existing profile, project, series, media, assets and jobs tables are reused.
- The existing worker accepts the v2TakeId job snapshot reference and attaches video and storyboard outputs to the correct take.
- The cloned database retains original scenes/shots, but v2 doesn't need the old production pipeline. The first open imports existing scene text into the v2 editor if present.

## Present limitations

This remains an experimental v2 implementation. EDL supports straight cuts only; source trim, transitions, audio mixing, colour and mastering stay in Resolve. Take duration in the handoff is the requested value and isn't yet reconciled to measured media duration. Concurrent screenplay editing is rejected rather than collaboratively merged. Provider keys continue to come from the existing server-side environment settings.

The v2 branch includes typechecking, server integration tests and a build workflow. Use bun install, bun run typecheck, bun test and bun run build to validate. The original bun.lock needs to be regenerated by bun install before frozen-lockfile installs become appropriate again.
